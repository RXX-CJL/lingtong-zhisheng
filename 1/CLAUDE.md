## 四条规则（从五个真实 bug 反推出来的，每条都付过代价）

### 1. 降级必须留痕

任何"依赖找不到就返回空/None、主流程继续跑"的路径，
**必须同时写 WARN 日志并在 `/status` 暴露状态字段**。

否则故障就是隐形的。已发生两次：
- `hyperlpr3` 没装 → 车牌永远为空，无人知晓
- PATH 上的 ffmpeg 是个坏 shim → 每次转码失败，静默回退 mp4v

### 2. 场景几何没标注就不判

停止线、禁停区、车道方向这类由**场景决定**的参数，
没有人工标注时必须是"禁用"，不能拿一个默认值兜底。

反例：禁停区曾默认成"画面下半部分" + 5 秒阈值 →
等红灯的车全被判违停，历史库里躺着 131 条误报。

### 3. 类型定义要能容纳真实数据

数据库里可能出现的 null，Pydantic 模型就不能写成非空。
反例：`track_id: int` 遇到一条 null 记录，整页 500，翻到第 5 页就崩。

### 4. 外部依赖要试跑，不能只看存在

`which('ffmpeg')` 找到不等于能执行。Windows 上 `.CMD` shim 可能指向已删除路径。
**验证方式是跑一次 `-version` 看退出码。**

## 这个项目的三个陷阱

1. **`zhitong/` 是历史遗留**，新代码一律放 `api/`，不要往旧目录加东西。
2. **测试数字不可信**。`pytest` 报 1047 失败，其中 1030 个是同一个测试
   遍历历史事件放大的。验证功能用新数据，别靠测试。
3. **默认只绑 `127.0.0.1`**。局域网访问要用 `start-all.bat --lan`，
   手机连不上不是故障，是设计。

## 改完代码怎么验证

```bash
# 1. 语法
cd api && ..\.venv\Scripts\python.exe -m py_compile <改动的文件>

# 2. 重启
E:\output\1\restart-backend.bat --lan

# 3. 跑真实视频，看 /api/realtime/status 的 processed_frames 和 violation_count
#    不要用真实路口视频判断误报——先跑一段"正常通行"的视频看是否零违规
```

**报"完成"之前必须拿得出证据**：命令输出、接口返回、画面截图，三选一。
