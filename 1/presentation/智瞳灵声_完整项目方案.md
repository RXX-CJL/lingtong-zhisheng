> 宁夏理工学院 · 电气信息工程学院

## 一、项目定位

### 1.1 项目愿景

**让每一次出行都更安全。**  
我们的愿景是构建一套"预测 — 发现 — 治理 — 评估"全链路闭环的 AI 交通治理智能体网络，用数据智能重塑城市交通治理范式。

### 1.2 核心使命

以边缘 AI 目标检测为基础，以云端大模型推理为增强，以多 Agent 协同决策为核心，为城市路口、校园周边、园区、商业综合体等场景提供低成本、可落地、可进化的交通治理解决方案。

### 1.3 项目口号

**让每一次违规都有预见，让每一寸道路都可治理。**

### 1.4 产品定位矩阵

| 维度 | 产品定位 |
|------|---------|
| 不是什么 | 不是一台单纯的摄像头，不是一个单一的 YOLO 识别工具，不是一个仅能录像取证的传统电子警察 |
| 是什么 | 一套端云协同的"AI 交通治理智能体"平台，集感知、分析、预测、执法于一体 |
| 对谁提供 | 政府（交警/城管）、企业（物业/物流）、高校（实验室/竞赛/教学） |
| 解决什么 | 违规发现难、执法响应慢、治理成本高、取证不可信四大核心问题 |

## 三、竞品对比分析

### 3.1 竞争格局

```
传统硬件大厂: 海康威视、大华股份、宇视科技
云平台方案: 阿里云交通云、百度智能交通、腾讯智慧交通
AI算法厂商: 极视角、旷视、商汤科技
开源/高校: 各类 YOLO 开源项目、学生竞赛Demo
```

### 3.2 核心对比表

| 对比维度 | 海康/大华 | 阿里云/百度云 | 极视角/算法包 | **智瞳灵声** |
|------|---------|-------------|----------|---------|
| 核心定位 | 硬件+AI取证 | 云端交通大脑 | 算法API/SDK | **端云协同智能体** |
| 推理延迟 | >200ms | >500ms | >50ms | **<50ms** |
| 断网能力 | 无法识别 | 完全失效 | 有限 | **离线可用** |
| 预测能力 | 无 | 基础流量 | 无 | **违规趋势预测** |
| Agent协同 | 无 | 有限 | 无 | **四Agent闭环** |
| 自进化学习 | 版本固定 | 平台迭代 | 算法更新 | **用户反馈驱动** |
| 部署成本 | 高（施工+硬件） | 高（平台+API） | 中 | **低（笔记本/摄像头）** |
| 适合场景 | 主干道固定点位 | 城市级指挥中心 | 算法替换 | **园区/路口/移动** |

### 3.3 我们的核心差异化

1. **端云协同架构**：边缘承担 90% 实时推理，云端仅处理模糊样本，速度与准确度兼得；
2. **多 Agent 决策**：感知 / 分析 / 预测 / 执法四大 Agent 协作，远超传统"单AI一次性识别"；
3. **预测式主动治理**：从"事后发现"升级为"事前预防"——LSTM+GNN 预测 2 小时后违规趋势；
4. **自进化持续学习**：用户审核→自动标注→模型微调→Shadow 测试→线上部署，系统越用越聪明；
5. **低成本可落地**：单路口部署成本是传统电子警察的 1/10，无需施工即可交付。

## 四、整体技术架构

### 4.1 五层架构总览

```
┌──────────────────────────────────────────┐
│  治理层：Web后台 + 微信小程序 + 大屏展示  │
│  实时告警 · 执法报告 · 证据链 · 热力图    │
├──────────────────────────────────────────┤
│  Agent决策层：感知/分析/预测/执法四Agent  │
│  多模态大模型推理 + 规则引擎 + 知识图谱  │
├──────────────────────────────────────────┤
│  云端AI层：豆包大模型 + 阿里云 ECS        │
│  模糊样本二次确认 · 数据存储 · API服务    │
├──────────────────────────────────────────┤
│  边缘计算层：TensorRT + YOLOv8 + DeepSORT │
│  RTX 4060 / Jetson 边缘设备 · 15ms/帧    │
├──────────────────────────────────────────┤
│  感知层：USB摄像头 / 网络摄像头 / K230     │
│  30fps · 1080P · 多路并发                │
└──────────────────────────────────────────┘
```

### 4.2 数据流向

摄像头视频流 → YOLOv8 目标检测 → DeepSORT 轨迹跟踪 → 违规判据引擎 → 综合置信度评估 →
- 置信度 ≥ 0.8：本地处置（语音告警 + 即时记录）
- 置信度 0.5-0.8：云端豆包大模型深度确认
- 置信度 < 0.5：不触发，忽略

最终统一入库：违规记录 + 证据截图 + 轨迹回放 + AI 推理链 → 管理平台展示 + 区块链存证。

### 4.3 核心技术栈

| 组件 | 选型 |
|------|------|
| 目标检测 | YOLOv8n（COCO预训练+交通场景微调） |
| 多目标跟踪 | DeepSORT（卡尔曼滤波+外观特征） |
| 推理加速 | NVIDIA TensorRT（FP16半精度） |
| 大模型推理 | 豆包视觉大模型 / DeepSeek 语义模型 |
| 云端服务 | 阿里云 ECS + 对象存储 + 微信小程序 |
| 管理前端 | Vue3 + Element Plus（Web后台） |
| 数据库 | SQLite（本地）+ PostgreSQL（云端） |
| 边缘硬件 | RTX 4060 Laptop / K230 开发板 / Jetson Nano |

## 五、违规判据引擎

### 5.1 四类违规识别规则

| 违规类型 | 触发条件 | 验证逻辑 | 关键参数 |
|------|---------|---------|---------|
| 闯红灯 | 红灯亮起后车辆越过停止线且未立即停止 | 红绿灯状态检测 + 轨迹与停止线比对 | 越线阈值10像素 |
| 逆行 | 跟踪轨迹方向与车道方向夹角>150° | 卡尔曼滤波估计速度向量+余弦相似度 | 夹角阈值150° |
| 未戴头盔 | 二轮车检测框内未检测到头盔 | 头盔检测子模型置信度<0.5 | 置信度阈值0.5 |
| 违法停车 | 禁停区域内目标停留>30秒 | 同ID连续30帧坐标变化<5像素 | 停留帧阈值30帧 |

### 5.2 综合置信度公式

```
综合置信度 = 0.6 × 检测置信度 + 0.3 × 跟踪稳定性 + 0.1 × 环境适配度
```

**检测置信度**：YOLO 目标检测输出置信度；  
**跟踪稳定性**：DeepSORT 轨迹的连续帧匹配率 + 位置误差；  
**环境适配度**：光照、天气、遮挡等因素的动态评分。

## 六、性能实测数据

> 测试环境：NVIDIA RTX 4060 Laptop GPU，1080P视频流，batch size = 1

| 指标 | PyTorch 原生 | TensorRT 优化后 | 提升幅度 |
|------|-------------|----------------|---------|
| 单帧推理延迟 | 45 ms | **15 ms** | **3.0倍** |
| 实时帧率 FPS | ~22 | **66** | **3.0倍** |
| GPU 显存占用 | 6.2 GB | 3.8 GB | ↓ 39% |
| 端到端全链路 | >180 ms | **<50 ms** | **3.6倍** |

**TensorRT 三大核心优化**：
1. 层融合：卷积 + BN + 激活函数合并为单内核；
2. 垂直融合：连续卷积拼接成大矩阵乘法，减少内核启动开销；
3. 内核自动调优：针对 RTX 4060 自动选择最优 CUDA 内核。
