# ChatGPT ↔ IDE/Codex 工作协议

## 标准流程

1. ChatGPT 读取当前基线和任务相关资料，定义目标、范围和验收标准。
2. 生成一个最小任务包，明确允许修改范围、禁止事项和验证命令。
3. IDE/Codex 先检查当前状态，再执行任务包。
4. IDE/Codex 返回变更文件、测试结果、证据、风险和剩余工作。
5. ChatGPT 审查差异和证据，给出 PASS、PARTIAL、FAIL 或 BLOCKED。

## 执行规则

- 不因旧文档声称完成就跳过验证。
- 不擅自扩大文件范围或顺便重构。
- 可逆且处于批准范围内的小修复可自行处理；删除、密钥、依赖安装、架构变化和范围扩大必须暂停上报。
- 测试失败必须保留原始错误，并区分环境问题、代码问题和外部服务问题。
- 结果报告优先使用一个结构化结果文件，避免大量重复中间文件。

## 状态定义

- PASS：目标和验收证据完整。
- PARTIAL：部分目标完成，仍有明确缺口。
- FAIL：目标未达成或引入回归。
- BLOCKED：因权限、外部服务、缺失输入或需要负责人决策而无法继续。
