# 摄像头接入指南（手机 / K230 / USB）

> 2026-10-03 由 DSH 编写。本文档回答"后期怎么把手机摄像头、K230 接进来"。
> 结论先行：**本项目已经把"视频文件"与"摄像头"统一成同一条代码路径**，
> 接入新设备不需要改代码，只需要给它一个"源标识"。

---

## 一、核心概念：统一数据源抽象

`realtime_detector.classify_source()` 会把传入的源字符串自动分类：

| 传入形式 | 识别为 | 循环行为 | 例子 |
|---|---|---|---|
| `http://` `https://` `rtsp://` `rtmp://` `udp://` `tcp://` `rtp://` 开头 | **stream** | **不循环**（持续流） | `http://192.168.1.5:8080/video` |
| 纯数字 | **camera** | 不循环 | `1` |
| 其它（本地路径） | **file** | **循环播放** | `E:\...\video.mp4` |

**这意味着**：
- 导入视频 = 一个会 EOF 的源（EOF 时回到开头循环，解决"视频时长有限"）
- 摄像头/手机/K230 = 永不 EOF 的源（`loop` 参数自动失效）
- **下游（检测/追踪/违规/证据/前端）完全无分支** —— 同一条流水线

**已实测验证**（见本文第五节）。

## 二、手机摄像头接入（推荐三种方式）

### 方式 A：IP Webcam（Android，最省事）
1. 手机装 **IP Webcam**（Play 商店免费）
2. 打开 App → 拉到最底 → **Start server**
3. 手机屏幕会显示地址，形如 `http://192.168.1.5:8080`
4. 浏览器流地址 = **`http://192.168.1.5:8080/video`**（MJPEG）
5. 在直播页填这个地址，源类型选「摄像头/流」，点开始

### 方式 B：DroidCam（Android/iOS，画质更好）
1. 电脑装 DroidCam 客户端，手机装 DroidCam App
2. 两种接法：
   - **WiFi**：手机显示 `http://192.168.1.5:4747/video`
   - **USB**：客户端会创建一个**虚拟摄像头**，此时用「本机摄像头」模式，索引填虚拟设备号
3. 本机已实测存在虚拟摄像头（索引 2、3），很可能就是这类工具创建的

### 方式 C：Iriun Webcam（iOS/Android）
- 类似 DroidCam，装好后电脑上出现虚拟摄像头，用「本机摄像头」模式 + 正确索引

### 关键：**怎么知道该填哪个索引？**
```powershell
# 本机摄像头枚举（会告诉你哪些索引真的有画面）
& C:\miniconda\envs\zhitong-gpu\python.exe E:\output\_scripts\_enum_cameras.py
& C:\miniconda\envs\zhitong-gpu\python.exe E:\output\_scripts\_grab_camera_frames.py
```
第二条会**抓一帧存成图片**，直接看内容判断是内置还是虚拟设备。
> 实测经验：DSHOW 后端下 `[0]` 可能是空画面，**真实画面在 `[1]`**；虚拟设备常见于 `[2]/[3]`。

## 三、K230 接入（只当摄像头用）

K230 官方例程自带 **RTSP / RTMP 推流**（`K230/程序源码` 下有 streaming 相关例程）。
按你的定位（"仅仅作为摄像头，不单独写代码"），**最省事的路线**：

```
K230 跑官方推流例程  ->  输出 rtsp://<k230-ip>:8554/stream
                     ->  本项目直接用「摄像头/流」模式填这个 URL
```

**注意**：
- K230 的 RTSP 默认端口常见 `8554`，具体看例程配置
- 若 K230 只支持 RTMP，也能用（`rtmp://` 已在分类白名单里）
- 网络：确保电脑与 K230 同网段
- **建议让 K230 输出 1280×720 或更高** —— 实测分辨率直接影响小目标（红绿灯、车牌）能否识别

**如果 K230 只能走 USB**（UVC 免驱模式）：它会表现为一个**本机摄像头**，
用「本机摄像头」模式 + 枚举出来的索引即可，同样不用改代码。

## 四、已知坑与注意事项

| 坑 | 说明 | 对策 |
|---|---|---|
| **索引 ≠ 设备顺序** | DSHOW 与 MSMF 后端的索引含义不同 | 用 `_grab_camera_frames.py` 抓帧确认 |
| **虚拟摄像头空画面** | 虚拟设备未推流时返回纯色帧（灰度标准差 < 3） | 脚本里有 `blank` 判定，看输出即可识别 |
| **Vite 代理阻塞** | 前端 `api` 实例走 Vite `/api` 代理；MJPEG 长连接会阻塞后续请求 | 前端已用 `realtimeRequest` 直连 `:8001` 绕过 |
| **局域网 IP** | 手机与电脑必须同网段；Windows 防火墙可能拦 8001 | 必要时放行 8001 入站 |
| **`FRAME_RATE=15`** | 摄像头源按 `FRAME_RATE` 抽帧处理，不是源帧率 | 需要更实时就调高；算力不足就调低 |
| **分辨率决定成败** | 640×480 下远处车辆/红绿灯只有几像素，算法无法判定 | 尽量 1280×720+ |

## 六、给 K230 的"最小约定"
如果你希望 K230 接入后**立刻能用**，只需满足：

1. 输出 **1280×720 或以上**（决定小目标可识别性）
2. 输出协议是 **RTSP / RTMP / HTTP-MJPEG** 之一
3. 与电脑**同网段**、无需鉴权（或把账号密码写进 URL：`rtsp://user:pwd@ip:554/stream`）

满足这三条，**无需任何代码改动**即可接入。
