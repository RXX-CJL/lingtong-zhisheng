# ★ 根因定位：通道多反转一次（2026-10-04 最终结论）

> **这是本轮最关键的结论。它推翻了本轮之前所有关于"颜色"的论断。**
> 责任方是**我的代码**，不是 CARLA、不是地图资产、不是相机设置。

---

## 一、根因（一行代码）

```python
# ❌ 我本轮所有脚本都这么写：
arr = np.frombuffer(image.raw_data, np.uint8).reshape(H, W, 4)[:, :, :3]
bgr = arr[:, :, ::-1].copy()          # ← 多余！把 BGR 变成了 RGB

# ✅ 正确：
bgr = np.frombuffer(image.raw_data, np.uint8).reshape(H, W, 4)[:, :, :3].copy()
```

**CARLA sensor 的 `raw_data` 字节序是 BGRA**，所以 `[:, :, :3]` 取到的**就是 BGR**，
可直接交给 OpenCV。再多做一次 `[::-1]` 会得到 RGB 却被当成 BGR 使用 → **红蓝互换**。

## 二、铁证（同一帧、两种读法、同一个橙色路障）

| 读法 | 橙色路障实测 | 判定 |
|---|---|---|
| A：`[:, :, :3][:, :, ::-1]`（我一直在用） | BGR=(239,236,231) hue=202 | ❌ B 最大 = 偏蓝 |
| **B：`[:, :, :3]`（正确）** | **BGR=(99,170,238) hue=30 sat=149** | ✅ **R 最大 = 橙色** |

像素级：`raw4=(88, 96, 105, 255)` → B=88 最小、R=105 最大 = **橙色**。

## 三、修复后的效果：红灯正常了

| 镜片 | Red 态（修复后） | Green 态 |
|---|---|---|
| 上（红灯位） | **BGR=(87,156,238) hue=28 橙红** | BGR=(37,51,65) 暗 |
| 下（绿灯位） | 暗 | BGR=(128,223,178) hue=90 绿 |

**红灯从"hue 214 青蓝"变成"hue 24–28 橙红"** —— 一个 `[::-1]` 就是全部原因。
