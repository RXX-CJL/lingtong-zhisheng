## 五、**待办（按优先级）**

### P0 — 判色范式重构 ⭐ 最重要
```
现状：判色是"统计整个灯框的主色" / "CNN 判整图"
问题：黄色灯箱占 95%+ 像素，点亮的灯珠（十几像素）被淹没
      -> 实测：即使灯框 186x371 px，三态黄色像素仍都是 18000+，判色无效
正确范式：
  ① 灯框内先找【发光区域】（高饱和 + 高亮 + 小面积连通域）
  ② 只对该区域判色
  ③ 找不到发光区 -> unknown（不猜）
```
**这是"判色"能否可信的关键。**

### P1 — 测速精度
```
现状：ground_plane 几何模型已启用（ppm 从 108.68 修正到 63.48）
问题：缺省相机参数(8m/-20°)与实际(7m/-22°)不匹配 -> 实测仍偏约 -28%
      （真值 30 km/h，实测 21.7）
解：用【场景标注工具】把实际相机参数标进去，再复测
```

### CARLA 特有坑
| 坑 | 正确做法 |
|---|---|
| `tl.bounding_box.location` 是**灯杆坐标系内偏移**，不是世界坐标 | 用 `get_light_boxes()` 拿灯珠真实世界坐标 |
| `tf.transform(vector)` 对**向量**只旋转、**不加平移** | 用 `t.location + t.transform(offset)` |
| 红绿灯灯面法线是 **±X**（信号头 `ext` 最薄的轴）| 不要用杆的 yaw 算 ±Y，会拍到侧面 |
| 默认红绿灯 **红灯只 2 秒**（绿10/黄3/红2）| `set_green_time/set_red_time` 需在 `freeze(True)` 状态下设才生效 |
| `set_state` 会被自动周期覆盖 | 配 `freeze(True)` 才能钉死 |
| CARLA 启动慢（约 30 秒），且**父 shell 退出会带走进程** | 用 `ProcessStartInfo` + `UseShellExecute=false`，或后台任务 |
| **CARLA 与检测后端抢显存会 OOM** | 错峰：录视频时停后端，跑检测时停 CARLA |
